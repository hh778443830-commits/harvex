# HARVEX — النسخة التأسيسية 0.2

تم إعداد المشروع ليعمل على Cloudflare Workers مع قاعدة D1. تم إدراج معرّف قاعدة البيانات الذي زوّدنا به المستخدم في `wrangler.jsonc`:

`9809ded9-4cd4-4a8c-aa1a-fe3e2d4c3907`

**تنبيه مهم:** إدراج المعرّف في الإعدادات لا ينشئ قاعدة البيانات في حساب Cloudflare. يجب أن يكون هذا المعرّف فعلاً لقاعدة D1 موجودة في الحساب نفسه، وباسم `harvex-db` أو عدّل `database_name` لاسمها الحقيقي.

## التجهيز والنشر

1. فك ضغط الملف وافتح مجلد المشروع في الطرفية.
2. نفّذ `npm install`.
3. طبّق الجداول على قاعدة D1 البعيدة: `npx wrangler d1 migrations apply harvex-db --remote`.
4. أضف مفتاح التهيئة السري: `npx wrangler secret put BOOTSTRAP_KEY`، واكتب قيمة طويلة عشوائية في الطرفية ولا تشاركها في المحادثة.
5. للتجربة المحلية: `npm run dev`.
6. للنشر: `npm run deploy`.

## إنشاء حساب المهندس لأول مرة

أرسل طلب POST إلى `/api/setup/first-engineer` مع JSON يحتوي `bootstrapKey`, `username`, `displayName`, `password`. يجب أن تكون كلمة المرور 12 حرفاً على الأقل. لا تضع مفتاح التهيئة أو كلمة المرور في ملفات عامة.

## ما تتضمنه النسخة

- واجهة عربية RTL متجاوبة.
- تسجيل دخول وجلسة آمنة بملف ارتباط HttpOnly/Secure.
- إضافة العملاء وعرضهم.
- مخطط جداول للمواقع وأجهزة التسجيل.
- تخزين كلمات المرور باستخدام PBKDF2، وتخزين بصمة رمز الجلسة بدلاً من الرمز نفسه.

## ما لم يُنفذ بعد

هذه نسخة تأسيسية وليست جاهزة للإنتاج. لم يتم بناء تطبيق بوابة أندرويد أو النفق الآمن إلى شبكة العميل أو عرض البث الحي. كما يلزم قبل الاستخدام الفعلي إضافة تحديد معدل المحاولات، وسجل تدقيق، واستعادة الحساب، ومصادقة متعددة العوامل، واختبارات أمنية وعزل أقوى بين العملاء. توافق ONVIF/RTSP يعتمد على جهاز التسجيل وإعداداته.
